## 製品概要
### 背景(製品開発のきっかけ、課題等）

「目は覚めた。でも、ベッドから出られない。」
朝、アラームを止めたあと、ベッドの中でSNSや動画を見始めてしまう。「あと5分だけ」のつもりが、気づけば何十分も経過している。
私たちは、こうした目覚めてから実際にベッドを出るまでの時間に着目しました。
一般的なアラームでは、停止操作を行ったことは分かっても、実際にベッドから出たかどうかまでは確認できません。
そこで、アラームの解除条件を「画面上の操作」から「実際の離床行動」に変え、スマートフォンの利用制限とも連動させる仕組みを考えました。

### 想定ユーザー

OKI:LOCKは、起床後のスマートフォン利用や二度寝によって、ベッドから出るまでに時間がかかってしまう人を対象とした起床支援システムです。

この課題は特定の年代に限らず、幅広い人に共通するものだと考えています。

その中でも私たちは、**特に大学生にとって必要性の高い仕組みになるのではないか**と考え、主な想定ユーザーに設定しました。

大学生は授業の時間割やアルバイト、休日の予定などによって、曜日ごとに起床時刻や生活リズムが変化することがあります。

こうした生活の特徴に着目し、**日々の生活リズムに左右されず、無理なく継続利用できる起床支援**を目指しました。


### ユーザー調査・アンケート結果

私たちは、自分たちの経験から、「朝、目覚めた後もベッドの中で時間を過ごしてしまう主な要因の一つが、スマートフォンの利用にあるのではないか」と考えました。
そこで、この仮説を検証する第一歩として、起床後のスマートフォン利用実態や離床への影響を把握するため、28名を対象にアンケート調査を実施しました。

#### 📊 調査結果

- **89.3%（25/28名）** が、週1日以上、起床後にベッド内でスマートフォンを使用
- **71.4%(20/28名)** が、週5日以上、起床後にベッドや布団の中でスマートフォンを使用
- **46.4%（13/28名）** が、直近1か月でスマートフォン利用による離床の遅れを「よくある」「ときどきある」と回答
- **53.6%（15/28名）** が、ベッド内でのスマートフォン利用時間を減らしたいと回答
- **46.4%（13/28名）** が、離床に応じてアプリ制限が解除される仕組みを使ってみたいと回答


### 📊 アンケート調査・分析（FigJam）

起床後のスマートフォン利用に関するアンケート結果と、調査から得られた気づきをFigJamにまとめました。

[▶ FigJamでアンケート結果・分析を見る](https://www.figma.com/board/FfjUBtyj3vmLgX4cuU5QrS/%E7%84%A1%E9%A1%8C?node-id=0-1&t=GIT3apXMyrctJJnW-1)

#### 💡 調査から得られた気づき

アンケートの結果、回答者の**71.4%が週5日以上、起床後にベッド内でスマートフォンを利用**しており、多くの回答者にとって日常的な行動であることが分かりました。

また、**46.4%がスマートフォンの利用によって離床が遅れた経験がある**と回答し、**53.6%がベッド内でのスマートフォン利用時間を減らしたい**と考えていました。

これらの結果から、起床後のスマートフォン利用は日常的な行動である一方、その利用によって予定していた離床が遅れ、改善したいと感じている人も一定数存在することが分かりました。

そこで私たちは、**「目を覚ますこと」と「実際にベッドから出ること」は別の課題である**と捉え、スマートフォンを使いたいという欲求を離床の動機に変える仕組みを考案しました。

一方で、提案した仕組みへの利用意向は46.4%にとどまっており、誰もが利用を望むわけではないことも確認されました。そのため、OKI:LOCKでは、利用者が制限対象のアプリを選択できることや、日々の追加操作を抑えることも重視しています。

※本調査は28名を対象とした探索的調査であり、一般人口全体の傾向や製品の効果を証明するものではありません。



### 既存手法の課題とOKI:LOCKの独自性

私たちは、起床後のスマートフォン利用によって離床が遅れてしまう問題に対し、既存のアプリ制限や起床支援サービスでは十分に対応しきれない場面があると考えました。

そこで、既存手法の課題を整理し、**ハードウェアによる継続的な在床・離床検知と、スマートフォンのアプリ制限を組み合わせる仕組み**を考案しました。

#### 1. 時間指定型のアプリ制限では、不規則な生活リズムに対応しにくい

大学生は授業の時間割やアルバイト、休日の予定などによって、起床時刻が日ごとに変化することがあります。

そのため、スクリーンタイムなどの時間指定型のアプリ制限では、実際の起床状況と制限時間が合わなかったり、予定に合わせて設定を変更する手間が生じたりします。

**OKI:LOCKでは、時刻ではなく実際の在床・離床状態に応じてアプリ制限を切り替えることで、不規則な生活リズムにも柔軟に対応できます。**

#### 2. 一度きりの解除ミッションでは、二度寝の可能性が残る

既存の起床支援アプリには、QRコードの読み取りなど、ベッドから離れる行動を求めるものがあります。

しかし、一度ミッションを達成してアラームを解除しても、その後ベッドに戻って二度寝したり、スマートフォンを使い続けたりする可能性があります。

**OKI:LOCKでは、圧力センサによって離床後の再入床も検知し、再アラームによって二度寝への対応を図ります。**

#### 3. 起床確認だけでは、「目覚め」と「離床」を区別できない

起床確認の通知やアラームの停止操作に応答したとしても、実際にはまだベッドの中にいる可能性があります。

私たちが解決したいのは、単に目を覚ますことではなく、**目覚めた後にベッドから出られず、朝の時間を有効に使えないこと**です。

**OKI:LOCKでは、ベッドに設置した圧力センサによって実際の離床状態を検知し、アラーム停止とアプリ制限解除の条件にしています。**

#### 4. 継続利用を考慮した操作負担の軽減

起床支援の仕組みは、毎朝継続して使えることも重要です。

毎日の解除ミッションや、生活リズムに応じた制限時間の設定変更は、利用者の負担になる可能性があります。

**OKI:LOCKは初期設置こそ必要ですが、その後は自然な離床動作を利用するため、日々の追加操作を抑えられる設計です。**

#### OKI:LOCKが提供する価値

| 既存手法で想定される課題 | OKI:LOCKの解決アプローチ |
|---|---|
| 固定された制限時間が生活リズムに合わない | 在床・離床状態に応じたアプリ制限 |
| アラーム解除後にベッドへ戻ってしまう | 再入床の検知と再アラーム |
| 起床確認に応答してもベッド内にいる可能性がある | 圧力センサによる実際の離床判定 |
| 毎日の設定変更や解除ミッションが負担になる | 初期設置後の操作負担を軽減 |

#### なぜハードウェアを使うのか？

**「アラームを止めたか」ではなく、「実際にベッドから出たか」を判定するためです。**

圧力センサを用いることで、スマートフォン上の操作だけでは把握しにくい在床・離床状態を継続的に検知できます。

この情報をアプリ制限やアラーム制御と連動させることで、生活リズムへの柔軟な対応、二度寝への対策、操作負担の軽減を目指しました。

**時間ではなく、行動でスマホを制御する。**

これがOKI:LOCKの独自性です。


### 製品説明（具体的な製品の説明）
朝活したい人・朝の無駄な時間を減らしたい人のための目覚まし。ベッドの下に圧力センサを置き、「ベッドから出たかどうか」で起床を判定する。
アラームはベッド脇の M5Stack から鳴り、スマホアプリから Bluetooth (BLE) でセットする。ベッドの上にいる間はスマホがロックされ、アラームもベッドを出るまで止まらない。アラームが止まると、事前に登録しておいた「朝やること」が表示される。（「朝やること」については後ほど説明があります）

#### 2. 二度寝を自動で検出して再アラーム
起床後20分以内にベッドへ戻ると二度寝とみなし、戻ってから10 / 20 / 30分後（アプリで選ぶ）にもう一度鳴らす。3度寝はその場ですぐ鳴らす。


#### 3. 朝の活動をサポートする任意のルーティン機能

OKI:LOCKが目指すのは、単に目を覚ますことではなく、ベッドから出て一日の行動を始められるようにすることです。

そこで、離床後の行動をサポートする補助機能として、事前に登録した「朝やること（MORNING ROUTINE）」を表示します。

この機能はあくまで任意であり、ルーティンの達成や操作をアラーム停止・アプリ制限解除の条件にはしていません。

**アラームを止めるために必要なのは、ベッドから出ることだけ。**

日々の追加操作を必要としないシンプルな起床体験を維持しながら、希望するユーザーには朝の活動を始めるきっかけを提供します。


#### 4. QR で登録したスマホだけがつながる
M5Stack の画面に表示した QR を読んだスマホとだけ、暗号化した BLE で通信する。意図しない他人のデバイスとはつながらない。

### 解決できること

「アラームを止めたのに、ベッドから出られない。」

OKI:LOCKは、起床後のスマートフォン利用による離床の遅れや、二度寝につながる行動を減らすことを目指します。

時間や複雑な解除操作に頼らず、**ベッドから出るという自然な行動を、アラーム停止とアプリ制限解除の条件**にすることで、生活リズムに左右されにくい起床体験を提供します。

さらに、希望するユーザーには朝のルーティン機能を通じて、離床後の活動もサポートします。

**「目覚める」から「ベッドを出る」へ。そして、一日の第一歩へ。**

「明日こそ」を「今日、朝から」に変える。

#### ハードウェアの低コスト化・小型化

現在の試作品では、開発のしやすさや動作確認を重視し、ディスプレイやスピーカーを備えたM5Stack Basicを採用しています。

一方、実用化に向けては、必ずしも同等の高機能な開発ボードを使用する必要はないと考えています。

今後は、離床判定・BLE通信・アラーム制御に必要な機能を整理し、より安価なマイコンや周辺部品への置き換えを検討します。

これにより、ハードウェアの小型化と製作コストの削減を目指します。


### 注力したこと（こだわり等）
* アラームの鳴動・起床判定・二度寝判定は M5Stack 側で完結させ、スマホ側からはアラームを解除できない（ロック中は API が拒否する）
* アラーム音量はハードのボタンで調整でき、初期値はミュートではなく最小音量
* Wi-Fi 不要。M5Stack とスマホは BLE でつながり、時刻もスマホから受け取る（アラーム処理と重ならないタイミングでのみ反映）
* AIを開発に活用しながらも、生成されたUIをそのまま採用するのではなく、ユーザーにとって直感的で操作しやすい画面を目指し、レイアウトや視認性、操作の分かりやすさなど、細部まで調整を重ねた


### ハードウェア構成

OKI:LOCKでは、M5Stack BasicとFSR406圧力センサを用いて、ベッドの在床・離床状態を検知します。

スマートフォン上の操作だけでは判定しにくい実際の離床状態を、ハードウェアによって継続的に検知することで、アラームやアプリ制限と連動させています。

#### 使用デバイス

- **M5Stack Basic**：圧力センサの値を取得し、在床・離床判定やアラーム制御を行う
- **FSR406（圧力センサ）**：ベッドにかかる荷重の変化を検知する
- **Androidスマートフォン**：BLE通信によってセンサの状態を受け取り、対象アプリの利用を制限する

#### ハードウェアの工夫

圧力センサを用いて、ユーザーによる特別な解除操作を必要とせず、自然な離床動作によってアラームを停止できる構成としました。

また、アラーム制御をM5Stack側で行うことで、スマートフォン上の操作だけではアラームを解除できない仕組みとしています。


### セキュリティ（QR ペアリングと暗号化通信）
アラームを止めたいのは、寝ぼけた**本人**です。BLE に誰でも命令を送れると、ほかのスマホや nRF Connect から `cancel` を書き込むだけでアラームを止められ、ロックも外せてしまいます。そこで、**M5Stack の画面に表示した QR をカメラで読んだスマホだけ**が操作できるようにしました。

* M5Stack の右ボタンを長押しすると、LCD に QR を表示します（ベッドの外にいるときだけ）。アプリのホームにある「デバイスを追加」で読み取れば登録が終わります。一度登録すれば、以降は自動で暗号化して接続します
* QR には M5Stack の公開鍵（P-256）と使い捨てのトークンが入っています。スマホは ECDH で鍵を共有し、以降の通信はすべて AES-256-GCM で暗号化・改ざん検知します
* アプリにカメラの権限は不要です（Google Code Scanner を使用）。共有鍵は Android Keystore で暗号化して保存します

| 想定する脅威 | 対策 |
|---|---|
| 第三者が BLE でアラーム解除・設定変更を書き込む | 認証前のフレームと平文の命令はすべて捨て、LCD に `BLOCKED` 回数を表示する |
| 寝ぼけた本人が別のスマホを登録して止める | QR はベッドの外でしか表示できない。表示は120秒で、トークンは1回きり |
| 偽の M5Stack がロック解除の状態を送る | 公開鍵は QR から直接受け取る。GCM の検証に失敗した状態は信用しない |
| 睡眠・在床データの盗聴 | AES-256-GCM で暗号化する。認証前はセンサー値を送らない |
| 通信を録って再送する（リプレイ・反射） | 接続ごとの nonce、方向ごとに増えるカウンタ、IV に方向を入れる |
| QR の一部（公開鍵）をすり替える | devId = 公開鍵のハッシュなので、アプリが不一致を検出する |
| 会場にほかの M5Stack がある | 登録した `WakeUp-<devId>` にだけ接続する |
